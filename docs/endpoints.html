Endpoint Set Redesign

Orientation

How a number gets made

Enough of the existing machinery to follow the rest.

spec/endpoints.json holds the forty endpoints. harness/plan.py expands each into 64 concrete pre-resolved requests, spec/sequence.json pins a 100,000-long replay order drawn by weight, and every driver replays that file rather than filling templates itself.

The order interleaves hard: the first twenty slots hold fifteen distinct endpoints. That matters for everything below, because it means any two endpoints are measured microseconds apart on the same process, at the same JIT state, the same heap occupancy, the same thermal state.

Every statistic rolls up from one place. harness/summarize.py:102 states it: an endpoint is a histogram, a family is its endpoints merged, the blend is every family merged. The raw JSONL carries one histogram per endpoint per rung at 3.7 KB dense; the summary drops them and keeps only count, errors, mismatch, p50_us, p90_us, p99_us, p999_us and the two ratios.

The headline is the time the target took. It is comparable to the other targets in the run that produced it, because they shared a machine and a window.

Decisions

What changes, and why

Ten calls. The reasoning is here because a decision without it gets re-litigated.

Drop ep.boom

Cut

Remove the 500 from the blend entirely. The 4xx endpoints stay.

Why Suite B's error-handling delta already runs unhandled-500 as an arm against ok-200 on one long-lived process, which the plan calls the most portable measurement in the benchmark. In the blend the same row measures stack-trace capture policy rather than framework speed — the plan's own words are that it "dominates on the JVM and .NET and differs by whether the framework captures on every error or only when something logs it." That is configuration, not framework. The contract is also ambiguous across languages: a Go handler that panics and one that writes w.WriteHeader(500) exercise unrelated machinery, so making targets comparable means mandating which, and then the benchmark is measuring its own spec.

Cut or demote ep.forbidden

Undecided

A 403 in the blend has no mechanism behind it, because there is no auth in the blend.

Why It is a constant-cost status write, which is roughly what ep.missing_order costs minus the lookup. Suite B's authorization delta carries denied-403 as an arm where it means something, since there the principal and claim set actually get built before the rejection. Keeping it is defensible if the intent is coverage of the status code itself rather than of a mechanism.

Keep the three 4xx that have mechanisms

Settled

ep.unmatched, ep.missing_order and ep.malformed stay.

Why Each has distinct machinery behind it. A routing miss genuinely differs on whether it short-circuits before the middleware chain or walks all of it. ep.missing_order is a 404 raised by a handler that did a lookup first. ep.malformed is the validation rejection path.

Validation stays in _shared/domain.*

Settled

Do not move validation into each framework's native facility. Every target keeps calling the shared function.

Why This is already how it works and it is the reason the blend means anything. targets/node/_shared/domain.js:174 and targets/go/_shared/domain.go:582 hold the validators, both collect-all, and every target calls them — Fastify included, at targets/node/fastify/app.js:62, which hands req.body straight to the shared function instead of using a JSON Schema. Gin's ShouldBindJSON at targets/go/gin/main.go:35 only decodes into a map[string]any before calling the same code. Node carries no validation library at all and go-playground/validator sits in go.sum as an indirect dependency nothing imports.

The cost is real and worth stating plainly: the blend cannot show a framework being good at validation, and Fastify's compiled schema is bypassed. That is the price of every target doing identical work.

The shared validators are spec artifacts

Settled

They need a written contract on how they are implemented, not only on what they emit.

Why Within a language the validator is one compiled function, so it cancels out of every comparison. Across languages they are independently hand-written and conformance only checks the 422 body. Whoever writes the Java validateOrder therefore sets a constant offset that lands on every body_validate endpoint for every Java framework. The contract should pin a single pass, fixed field order, no reflection, and no regex unless the spec asks for one.

Fail-fast is two endpoints, not an option

Settled

Two 422 endpoints over the same payload with different mandated contracts. One must report the complete error set. The other must report only the first error and may stop there. Both live in the shared domain code, so every target gets both.

Why Short-circuiting saves nothing on a valid payload, because reaching a 200 means checking every field, so the fast path can only be measured where validation fails. Making it optional does not work either: "if the framework has it built in" is a judgment call, and under shared domain code any target can short-circuit with an early return, so the distinction collapses. Mandating both contracts means nobody chooses anything, nobody is excluded, and the delta between the two endpoints is the saving stated as a number rather than granted as a discount. Make the payload fail on its first field so the gap is large enough to read. Full validation stays the requirement, which is the actual position.

Matched pairs, one factor at a time

Settled

Endpoints come in pairs that differ in exactly one property, built by varying one factor from a common base rather than crossing everything.

Why Both halves of a pair land in the same rung microseconds apart, so a pair delta is cleaner than Suite B's arms, which are minutes apart on the same process. Same moment beats same process. Anything expressible as two endpoints should be; Suite B keeps only what needs a different process, such as boot-time server options or a protocol change.

The discipline is what keeps it finite. Size, validation, compression and shape fully crossed is 36 endpoints for one family. A base plus one arm per factor is seven, and yields the same deltas. Fully cross only size against validation: three sizes by two states, plus a 422 at each size, is nine.

Pin the compression codec per language

Settled

One algorithm and one level per language, the way Suite B pins the crypto library.

Why Compression cost is dominated by codec and level, not by framework, so an unpinned codec repeats the ep.boom mistake. The framework-relevant signal is whether the response is buffered whole before compressing or streamed, and whether compression is skipped below a size threshold — which is exactly why it has to cross with payload size.

Make the pairing machine-readable

Settled

Each endpoint in endpoints.json gains base and varies.

Why The site can then compute and show a delta column itself instead of the reader finding two rows and subtracting, and each generated endpoint page can state "costs 41 µs over pl.json_m" as generated text. It turns a naming convention into a feature for almost no code.

Readers compose their own blend

Settled

Let the reader choose which endpoints roll into the aggregate, with the default mix as the starting point.

Why It retires three arguments at once. Weights stop being an opinion, because anyone who disagrees reweights and gets their own number. Diagnostic pairs stop needing a separate unweighted sweep, since they can ship at zero default weight and stay selectable. And the fail-fast endpoint needs no policy: publish both and let the reader decide whether their traffic short-circuits.

One constraint sets the shape. Percentiles do not compose from percentiles, so the browser needs histograms, which the summary currently drops. Compute the ratio from composed histograms — merge the target's selection, merge the baseline's same selection, then divide — never by averaging per-endpoint ratios. Renormalize surviving shares to 10,000 by default and allow a manual override. Put the selection in the URL hash, like every other piece of view state, so a composed blend is a shareable link.

"Pin work" marks endpoints whose contract currently permits two conforming implementations that do materially different amounts of work. Whether jr.product_list sorts and slices the fixture per request or returns a precomputed page is a large difference that conformance cannot see, because the bytes come out the same. The nested_fetch family is the sharpest case: its stated purpose is a deeper middleware chain, and nothing pins how deep.

Risk

The hole worth closing first

Sixty-four instances is memoizable

harness/plan.py:13 sets INSTANCES = 64, so each endpoint has 64 distinct pre-resolved requests and no more. A target could precompute all 64 responses into a map at boot and reduce every endpoint to a dispatch and a write. Conformance would not catch it, because the bytes are identical by construction — that is the whole point of the fingerprint.

It has not happened, and every target lives in this repo under review, so the practical fix is a written rule plus review. Raising the instance count is cheap insurance and makes precomputation impractical rather than merely forbidden. Worth settling before the target set grows past two languages and review stops being one person reading everything.

Static HTML with no JavaScript, on the same origin as the table, so the link from a row is a plain href. Prose lives in markdown rather than in endpoints.json so it stays reviewable in a diff and does not bloat a file that plan.py reads on every build.

What each endpoint page carries

The identity line — id, family, method, path, expected status, share. What it exercises and why it earns a slot. Which fixture params it draws and how they correlate. The exact response contract including the field set. Implementation notes covering what a target must and must not do, which is where the "pin work" rulings land. And the captured request and response bytes from results/exemplars/, which already hold all forty per target per host.

Plan

Order of work

  1. Settle the open questions

    Everything marked undecided above. Cheapest to change now, most expensive once forty pages describe it.

  2. Write site/endpoints.py

    Reads spec/endpoints.json for structure, spec/endpoints/*.md for prose, one exemplar for wire bytes. Emits the index and the detail pages.

  3. Wire it into the site build

    Pass the docs directory through site/tools/build.js and add the route. The --out tree gains one subdirectory.

  4. Link from the results table

    At endpoint granularity the detail cell the explorer writes in site/src/client/explorer.ts renders the id as text. It becomes an anchor to endpoints/<id>.html.

  5. Add the parity check

    A validate job that fails when an id has no markdown file or a markdown file names an id that does not exist, matching how the spec drift check already works.

  6. Write the eight family files

    Highest-value prose in the set, because this is where "must do" and "must not do" get stated before another language lands.

  7. Write the forty endpoint files

    The bulk of the work, and mechanical once the families set the rules.

  8. Then the new endpoints

    Pairs, sizes, the two 422 contracts. Adding them after the doc pipeline exists means each arrives documented.

  9. Then histograms and the composer

    Carry histograms into the summary, ship them sparsely, build the endpoint selector. Independent of everything above and can run in parallel.

Open

Still undecided

Whether ep.forbidden survives as a status-code coverage row or moves to Suite B's authorization delta where it has a mechanism.

Where the echo endpoints belong. They sit in body_validate and do no validation, while a write_echo family exists and the family note reads "parser, schema validation, error paths". Either they move or the note is wrong. Related: nothing currently forces the echo response to be re-serialized from a parsed model rather than piped through as bytes, which is a large difference. Specifying a canonical key order for the response that differs from the request order would make a byte passthrough fail conformance.

Whether bv.rejected and ep.malformed measuring the same rejection path at two weights is deliberate coverage or an accident.

Exact byte counts for S, M and L, and whether M is chosen to sit on a buffer boundary or safely inside one.

Whether to add a native-validation family, where each target uses its framework's own validation facility and declares what it used. It would show Fastify's compiled schema and gin's struct tags, and it cannot be compared across languages. Worth having, worth labelling, and it cannot live inside the blend without taking the blend's meaning with it.

Whether the default blend mix stays as the published headline once readers can compose their own.
